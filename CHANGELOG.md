# Changelog

All notable changes to RapidCAM are documented here.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

---

## [Unreleased]

### Added
- **Laser rotary machining** — a new machine type, **Laser — Rotary (cylinder)**, engraves and cuts around a rod: tumblers, bottles, pens, bats. It combines the beam head with the cylinder stock model, so everything the rotary mill already had now applies to a laser — New Project asks for the stock as **Length × Diameter**, the wrapped canvas dimension stays locked to π·diameter (so the design covers exactly one revolution), the canvas shows the **wrap hint**, and the 3-D preview renders the burn on a **cylinder**. Export posts by **axis substitution** rather than wrapping: the wrapped axis stays an ordinary linear word in *surface millimetres*, and the program carries a banner stating what one revolution must measure so you can set the rotary's steps/mm from it (`Y steps/mm = steps-per-revolution / 251.327`). That is deliberate, not a shortcut — GRBL 1.1, which drives the great majority of laser rotaries, has no 4th axis and would reject an `A` word, and the drawing is already in the surface millimetres a substituted axis wants. The mill-only rotary controls (rotary axis word, Z0 reference, arc tolerance) hide for a beam, which emits none of them. Adds `"laser-rotary"` to `machineKind` in the `.rcam` format and JSON Schema.
- **Resize an image with constraints** — a placed image is still **rigid** by default (a constraint on a corner moves it), but its Properties panel gains a **Constraints** control that hands the solver more freedom when you want it: **Scale to fit** (uniform resize, rotation held), **Rotate to fit** (turn only, size held), **Scale + rotate**, or **Stretch to fit** (width, height and angle all free). The headline use is **calibrating a scan**: set *Scale to fit*, dimension a feature of known size on the image (edges and corners are dimensionable), and the whole image scales to suit — with the aspect ratio exact rather than approximately converged, because width and height are one degree of freedom in that mode. *Scale + rotate* lets two pinned corners place, size and turn the image in one go. Pick the narrowest mode that matches your intent: spare freedom lets the solver satisfy a constraint the wrong way, e.g. meeting a "level this edge" constraint by shrinking the image away. Adds an optional `constraintFit` field to the `.rcam` format and JSON Schema (omitted = `"rigid"`, so existing files are unchanged).
- **Export preview** — clicking **Generate G-code** now opens a confirm-before-you-cut screen: a top-down **backplot** of the actual posted program (rapids dashed/faint, cutting moves solid), the **estimated run time**, the job summary (toolpaths, stock, cut/rapid split), the target filename, and any **pre-flight findings** — all in one place, with **Export** / **Cancel**. It replaces the plain pre-flight confirm on the main export path (errors still gate behind an "Export anyway" button). The backplot is drawn from a new pure G-code→toolpath parser (`src/cam/gcodePath.ts`).
- **Job run-time estimates** — every toolpath card now shows an estimated cut time (⏱), and the generated G-code carries an `; Estimated run time:` header (total, split into cutting vs rapid). The estimate parses the actual posted program — feed moves at their feed rate, rapids at a default traverse rate, arcs by true arc length — so it covers mill, laser, and rotary (inverse-time) jobs alike and always matches what will run. It's a constant-feed ballpark (acceleration/deceleration and dwell aren't modelled, so jobs with many tiny moves run a bit longer in reality). Per-op estimates are computed off the render path and cached, so large raster/relief programs don't stall the toolpath list.
- **Dithered laser photo engraving** — a raster (image) engrave can now reproduce tone with a **1-bit dot pattern** instead of modulating beam power per dot. On diode lasers the power→burn response is very non-linear, so greyscale mid-tones come out muddy; dithering fires every dot at full power and lets *dot density* carry the tone, which maps far more predictably onto how a material scorches. Choose the algorithm in the engrave dialog's new **Dithering** dropdown: **Floyd–Steinberg** (the classic all-rounder), **Jarvis** (wider diffusion — smoother/softer), **Atkinson** (drops ¼ of the error for higher contrast — clean on wood and anodised aluminium), or **Ordered (Bayer)** (a fast, regular 8×8 pattern). Error-diffusion modes scan in a serpentine order to avoid directional artefacts. A live **magnified pattern swatch** under the dropdown shows the selected method's dot texture at one pixel per dot (the difference between methods is the dot arrangement, not the tone, so it's invisible at normal preview zoom). When dithering is on, **Min power** no longer applies (every dot is full power) and hides itself. The posted G-code carries the actual 1-bit dot pattern; the 3-D preview shows the resulting **tone** (a dither pattern's density-average is the source tone, and the height field is coarser than the dot pitch, so it reads the same as a greyscale engrave — which is what the burn looks like from a viewing distance). Adds an optional `rasterDither` field to the `.rcam` format and JSON Schema (omitted = greyscale power, so existing files are unchanged).
- **Align / Center** — a new **Align** toolbar (and right-click entries) centres the selected item(s) inside a container in one click: **Center H**, **Center V**, or **Center** (both). Select the thing to move plus the shape to centre it in — a rectangle (including one drawn as four separate lines), a circle, or another block — and click. The relationship is **fully live but one-way**: the mover re-centres as you edit it *and* follows the container when the container is moved or resized, while the container itself never moves. Implemented as a directional `center` constraint (the solver snapshots the reference centre each solve, so it drives the mover without ever being dragged by it); a reference with no single centre point uses the midpoint of its two diagonal corners. Adds the `center` constraint type to the `.rcam` format and JSON Schema.
- **Text is dimensionable** — a text entity now exposes its ink-box corners (`bl`/`br`/`tr`/`tl`), edge midpoints, and `centre` as snap/pick points, so you can dimension a text block's width/height or its distance from a nearby edge, and constrain those points like a rectangle's. The points are derived from the anchor plus the live glyph extents, so a constraint on one translates the (rigid) text and re-solves as the string is edited.

### Fixed
- The rotary wrap no longer drops inline words it doesn't interpret when it rewrites a motion line — above all a laser's `S` power (`G1 X.. Y.. F.. S255`), which would have vanished from every wrapped cut move and left the beam un-commanded. Words on an arc are now carried onto every chord it flattens into, so the beam can't drop out part-way round.
- Editing a text entity's string/font/size/angle from the Properties panel now re-solves, so a centring or alignment constraint re-flows to fit the change.
- Text centred against the bundled default font now stays centred when a design is reopened (the solve waited for the async font to load).
- A dimension drawn across a single text block's own box is created as a **reference** dimension (a text's size lives in its font, not the solver, so such a dimension can't drive it).

## [1.5.0] — 2026-07-11

Rotary jobs can zero to the cylinder centre, so the posted program lines up with
gSender's native rotary preview with no extra setup.

### Added
- **Rotary zero reference (surface or centre)** — a rotary (4th-axis) job can now choose where **Z0** sits: **Stock surface (top)** — the existing convention (touch off the cylinder top, cuts run negative) — or **Rotary centre (axis)**, the native rotary convention where Z0 is the axis of rotation, the surface sits at `Z = radius`, and cuts run toward the centre. Pick it in **Machine Settings** or **New Project** (shown for a rotary machine). Centre-zeroing matters for **gSender**: a centre-zeroed program renders correctly on the cylinder with **no** "Visualize non-center zeros" toggle, so the header's `; Cylinder Dia:` hint is omitted for that mode (surface-zeroed exports still emit it and still need the toggle). Whichever you choose flows through to both file export and **Send to gSender**. Adds an optional `zero` field to the `.rcam` `rotary` block (omitted = `"surface"`, so existing files are unchanged).

## [1.4.0] — 2026-07-10

Rotary (4th-axis) machining lands end to end — model on the unrolled cylinder,
post a wrapped A-axis program, and preview it as a real dowel — alongside
two-sided flip machining, positioned stock with fixtures, pre-flight G-code
checks, and a Send-to-gSender handoff.

### Added
- **Two-sided (flip) machining** — machine both faces of a part from a single drawing. Tag each toolpath **Top** or **Bottom** in its dialog, then **Generate G-code** produces a **side-A** program (the top ops, ending with **registration dowel-pin holes** bored through the stock into the spoilboard) and a **side-B** program whose geometry is mirrored about the flip axis so features line up through the part. Flip the stock onto the pins, re-zero, and run side B; the two files download as a zip (or hand them to gSender — side A, flip, then side B). Mirroring is done at the entity level, so leads, tabs, dogbones, and climb/conventional direction all come out correct on the reverse, and bottom-face **text engraves mirror-imaged** so it reads correctly from the back. A pre-flight check warns about asymmetric pins, a boring tool that can't cut a clean hole, and a top-side through-cut that would free the part before the flip. The 3D preview gets an **A/B side toggle** to see each setup as it will sit on the machine. Set it up from **Toolpaths → Two-sided (flip)…** (milling jobs). Adds an optional `flip` block and per-operation `face` to the `.rcam` format.
- **Rotary / 4th-axis machining** — a new machine type, **CNC Mill — Rotary / 4th axis** (alongside Mill and Laser in Machine Settings and New Project), machines around a cylinder: spoil rods, columns, rolling pins, pens. The drawing canvas becomes the **unrolled cylinder surface** — New Project asks for the stock as **Length × Diameter** (plus a radial wall / cut depth), and the wrapped canvas dimension is locked to π·diameter so the design always covers exactly one revolution (a straight line across the wrap becomes a **ring**, a diagonal becomes a **helix**). Every toolpath type works unchanged: at export the finished flat program is wrapped — the wrapped axis posts as **A/B rotary degrees** (arcs flattened to chords within a set tolerance) with **G93 inverse-time feed** so combined linear+rotary moves run at the commanded surface speed, restoring G94 at program end. Touch Z off the **top of the cylinder**. Pre-flight advisories catch a bad diameter or a flip/rotary clash. Adds `machineKind: "mill-rotary"` and a top-level `rotary` block to the `.rcam` format; see the bundled **Rotary Spiral Dowel** example.
- **Positioned stock & workholding** — the stock blank can now be a **placed rectangle inside a larger machine work area** instead of always filling the canvas (Settings gains separate **Work area** and **Stock** groups; the WCS origin follows the blank; the renderer draws the block). Layers gain a **fixture** flag: closed shapes on a fixture layer are **clamps/workholding**, not part geometry — drawn amber-dashed, never machined, toggled from the layers bar — with an optional per-layer **clamp height** above the stock. Adds `stockRect` and layer `fixture`/`fixtureHeight` to the `.rcam` format.
- **Pre-flight G-code checks** — every export (and gSender send) now lints the posted program first and shows the findings in a confirm dialog before any file is written: **rapids that travel sideways below the stock top** (a missing retract would plough through material), **moves outside the stock envelope** while engaged, **cuts below the stock bottom** (fine for a deliberate through-cut, flagged in case it isn't), **straight plunges fed at or above the cutting feed**, **a manual tool change with no active pause** (M0/M6), and **moves that would hit a fixture/clamp** (honouring each clamp's height for safe-Z rapids over it).
- **Send to gSender** — post the generated program straight to a running [gSender](https://sienci.com/gsender/) over its local API instead of downloading a file (configure the URL once in settings). A two-sided flip job sends **side A**, waits for you to flip onto the pins, then sends **side B**.
- **Three new bundled examples** — a **V-Carve Sign** (v-carve + chamfer sharing one v-bit through the tool library, tabbed profile cut), a **Laser Coaster** (ring engraves, fill-engraved lettering with overscan, kerf-compensated cut), and a **Rotary Spiral Dowel** (rings, helical flutes, and axial text on the unrolled cylinder). The format guide gains the missing `vcarve`/`score` rows and rotary/`circle-gap` documentation, and every bundled example is now also **behaviourally tested** (loads, solver converges, posts G-code) on top of schema validation.
- **Rotary G-code carries a diameter comment for visualizers** — the wrapped program's header now emits a machine-readable `; Cylinder Dia: <mm>` token (the DeskProto convention). Rotary senders such as **gSender** read it to wrap the toolpath preview around the cylinder instead of drawing the A-axis moves flat — in gSender, enable **Config ▸ Rotary ▸ "Visualize non-center zeros"** so it also offsets our surface-zeroed path onto the cylinder. The banner also spells out the surface-zero convention (Z0 = top of the cylinder).
- **3D preview shows the rotary cylinder** — for a rotary (4th-axis) job the built-in 3D cut preview now renders the carved stock as a **cylinder** — the engraving wraps around the dowel, rings stay rings and diagonals spiral into helical flutes — instead of the flat unrolled slab, and you can orbit the camera right under the dowel to inspect the underside. The unrolled/flat preview for ordinary milling and laser is unchanged.

### Fixed
- **Rotary `.rcam` files validate against the published schema** — the schema's `machineKind` enum was missing `"mill-rotary"`, so a saved rotary project failed validation against `rapidcam.app/schema/rcam-v2.schema.json` even though it loaded fine.
- **A rotary job can no longer be zeroed to a nonexistent "bed"** — a cylinder has no bed, but the Z-origin picker still offered "Bed" for a rotary machine. Choosing it shifted every Z by the radial wall thickness, so cuts posted high and the tool cut air while the header still claimed "Z0 = top". Rotary jobs are now always surface-zeroed on the cylinder top: the export ignores a stray bed origin on a cylinder (so old/hand-edited files are safe too), and the Z-origin control is locked to "Top of stock" for a rotary machine in both New Project and the settings panel.
- **Rotary cylinder preview no longer mirror-images the design** — the 3D cylinder preview wrapped the surface with the wrong handedness, so engraved text read reflected (most visibly on the underside). Preview-only — the G-code was always correct. The wrap now matches the flat preview's orientation. (No effect on any exported program.)

## [1.3.0] — 2026-07-04

DXF interchange lands in both directions — bring parts in from Fusion, LightBurn,
or a box-joint generator and hand them back out to a laser or cutting service —
alongside a round of dialog and modality hardening.

### Added
- **DXF import** — **File → Import DXF** brings parts in from the rest of the CNC ecosystem (Fusion exports, LightBurn libraries, box-joint generators, laser-cutting services). Reads LINE, CIRCLE, ARC, POINT, LWPOLYLINE and legacy POLYLINE — **bulged polyline segments become true arcs** (not tessellation), so the arc-fitting G-code posts keep real `G2`/`G3` moves — plus SPLINE (NURBS, tessellated), ELLIPSE (tessellated), and INSERT block references expanded with rotation and uniform scale. Honours the file's `$INSUNITS` (inch files scale to mm automatically; unitless files assume mm with a note). Imported geometry arrives selected, grouped under the filename, and the view zooms to fit; anything unsupported (TEXT, HATCH, dimensions…) is skipped with a warning summary instead of silently dropped.
- **DXF export** — **File → Export DXF** writes the drawing as a minimal DXF for handoff to LightBurn, QCAD, LibreCAD, Fusion, or a cutting service: true ARCs, closed/open LWPOLYLINEs, **béziers as exact SPLINE curves** (a cubic bézier is a degree-3 NURBS — no tessellation), POINTs, and text as engraveable outline polylines (falls back to a DXF TEXT entity when the font isn't available). Layer names are preserved; construction geometry and hidden layers are excluded. Export → re-import round-trips exactly.

### Fixed
- **New Project no longer inherits the old project's CAM state** — creating a new project used to carry over the previous drawing's toolpath operations, variables, bindings, groups, layers, and job metadata (e.g. an old mill profile op showing up in a fresh laser project). The document reset now clears every field.
- **Dialogs are properly modal** — editor keyboard shortcuts (Ctrl+N/O/S, undo, Delete, tool keys) no longer fire underneath an open dialog, **Escape** now closes the topmost dialog, and switching projects closes any dialog left open. This now applies across every dialog (New Project, Tool Library, toolpath editor, array/pattern generators, text, image adjust, material test, machine settings, share, feedback, privacy, and about). The pre-emptive browser confirm before **File → New** is gone: the New Project dialog itself shows a discard warning only when there's real work, so Cancel never loses anything.
- **Styled confirmations replace browser popups** — deleting a layer or a library tool, opening a recent file or example over unsaved work, and the missing-font export check now use in-app dialogs (and **Ctrl+O** now asks before discarding unsaved work — it previously didn't ask at all).
- **Toolpath cards no longer truncate** — the operation name and tool summary now use a two-row layout instead of squeezing into one line ("Pr…").
- **G-code export confirms** — generating or exporting toolpaths shows a toast with the file name instead of a silent download.

## [1.2.0] — 2026-07-04

Parametric modelling comes to RapidCAM: type variable formulas straight into
property fields, reference variables from other variables, drive and constrain
engrave images, and rough deep relief carves with a coarse tool before the
finish pass.

### Added
- **Parametric formulas in property fields (circle radius)** — you can now type a variable formula straight into a scalar property field instead of adding a dimension: enter e.g. `plateW/2` in a circle's **Radius** and it's driven by that formula (shown with an **ƒx** badge; click it to unbind, or type a plain number to go back to a literal). Under the hood it's a *headless binding* fed to the same constraint solver as dimensions — so a formula and a geometric constraint reconcile through one channel (no conflict), and over-constrained detection covers both. Stored in the `.rcam` as a top-level `bindings` array (additive). This is the first field wired; more scalar properties (arc radius/angles, and images) follow.
- **Parametric formulas now work across the common property fields** — building on circle radius, you can type variable formulas into an **arc**'s radius/start/end, a **line**'s length, and a **rectangle**'s W/H (all with the `ƒx` badge, click-to-unbind, and red flag when broken). Scalar-DOF fields (radii, arc angles) use headless bindings; measurement fields (line length, rect W/H) use *hidden driving dimensions* — a dimension that constrains the geometry through the solver but draws nothing on the canvas. Angle fields keep their degrees while the underlying scalar stays radians. New `.rcam` `dimension.hidden` flag (additive).
- **Variables can reference other variables** — a variable's value may now be a formula built from *other* variables (e.g. `margin = width * 0.1`), evaluated in dependency order so declaration order doesn't matter. Reference cycles (including a self-reference) are detected and leave those variables at their last value instead of looping. Plain lengths (`50mm`, `1/2in`) still parse unit-aware as before.
- **Parametric image sizing** — an engrave image's **Width**, **Height**, and **Angle** in the Properties panel now accept **variable formulas** (e.g. `plateW/2`), re-evaluated whenever a variable changes, so images resize/rotate parametrically alongside your other geometry. A pure number stays a literal; a formula shows the `ƒx` badge (click to unbind). This runs through the **same headless binding + solver** as every other scalar field — an image is now an ordinary solver body with `w`/`h`/`angle` scalar DOFs (no separate image formula path). **Lock aspect** persists on the image as an edit-time convenience: editing one of width/height writes a proportional value/formula to the other. Formulas are stored in the top-level `bindings` array (`scalarKey` `"w"`/`"h"`/`"angle"`); legacy files with the earlier `image.widthExpr`/`heightExpr`/`angleExpr` fields auto-migrate to bindings on load.
- **Images can be positioned with constraints** — an image now exposes its four **corners** and **centre** as snap/pick points, so you can constrain them to the rest of the sketch: e.g. an image corner *coincident* with a hole centre, or the image centre on a point, or a corner *on* a line/circle. The image reflows to follow when the geometry it's pinned to moves — so an engraving stays put relative to the part it decorates. An unconstrained image is treated as a **rigid body** (a constraint translates it; its size/rotation are set in the Properties panel or by formulas, not distorted to satisfy a single point constraint). Uses the same solver as every other constraint — no new `.rcam` fields (constraints already reference points by `{entityId, key}`; the new keys are `c0`–`c3` and `center`).
- **Broken parametric formulas are flagged, not silent** — if a formula (a driving dimension, a bound property field, or an image size/angle field) references a variable that's been deleted, the input is now outlined in red and a bound field's badge turns to a **⚠** (hover explains) instead of silently holding its last value — which could otherwise post a wrong toolpath.
- **Relief roughing (mill)** — a new **Relief Roughing (image)** toolpath clears the bulk of a greyscale-image relief in flat Z-levels with a coarse flat / bull-nose tool, down to a **finish allowance**, so the ball-nose relief **Engrave** (finish) pass only has to skim the last of the material. This makes deep photo/relief carves practical: the flat tool hogs out the waste fast, then the finishing bit gets a smooth surface without ever plunging full depth. It rasters at the tool's stepover, steps down in passes, **ramps into each cut** (rather than plunging straight down — easier on a flat end mill), hops over uncut areas at a low clearance, and shows a live cut-time estimate plus the roughed staircase in the 3-D preview. Add it *before* the finish Engrave op (with its own flat tool), and match its depth/stepdown/stepover/tone-curve/invert to the finish op — the toolpath list **warns** if a roughing op would cut deeper than its finish op's final surface (a gouge). New `.rcam` op `type: "relief-rough"` (additive).
- **File → Start Screen** re-opens the welcome splash on demand (Examples, Open, Restore Draft) instead of it only appearing at page load. When reopened mid-session it's dismissable (Esc or click outside), and its **New Project** goes through the same guarded path as File → New (confirms before discarding unsaved work).

## [1.1.0] — 2026-07-01

### Changed
- **CAM: Curved profiles with holding tabs now post smooth arcs.** Arc-fitting previously ran only on tab-free profiles; a profile *with* tabs was linearized to G1 facets end to end. Now each material-cutting run between tabs is arc-fit to G2/G3 (the tab bridges stay straight G1 at their raised height, as before), so a tabbed circle or filleted part cuts smoothly instead of faceted. Straight-edged tabbed profiles are byte-identical. The arc-fit keeps its ≤tol faithfulness guarantee, so no toggle is needed.
- **Constraints/dimensions on a polyline survive vertex edits.** Each polyline vertex now carries a stable id, and point keys (`v<id>`, `mid_<id>`) and segment-as-line refs (`<polylineId>#<startVertexId>`) are built from it instead of the array index. Previously, chamfering/filleting a corner — or resizing a polygon — inserted or removed vertices and silently re-pointed every later constraint/dimension at the wrong vertex. The `.rcam` format gains an optional parallel `vertexIds` array on polylines (additive — files without it default each id to its index, so older files and keys load unchanged); documented in the [authoring guide](docs/rcam-format-v2.md) and [schema](public/schema/rcam-v2.schema.json).
- **Privacy: session replay is now its own opt-in.** Session replay captures the pixels of your on-screen drawing (the geometry lives in a `<canvas>` that DOM-only replay can't see), which the single "Allow analytics" consent never disclosed. Replay is now gated behind a separate, unchecked-by-default checkbox in the consent banner and a distinct localStorage key (`rapidcam_analytics_replay_consent`); allowing usage analytics no longer enables canvas recording. The README privacy section is corrected to match.
- **CAM: Optional leaner V-carve toolpaths** — a v-carve op gains a **hop clearance** (`vHopClearance`): set it above 0 and, within a carved region, the bit hops between contours at that low height above the stock surface instead of fully retracting to safe-Z every time — cutting the dozens of full-height retracts between the concentric peel rings of text and shapes. It defaults to **0 (off → retract to safe-Z)**, the safe choice: a low hop only clears the stock it travels over, not a hold-down clamp or fixture standing above the stock inside the carve. The first approach and final park always use safe-Z.

### Added
- **Engrave images can be flipped / mirrored.** Selecting an image and using **Flip H** / **Flip V** (Transform section) now mirrors it — previously flip was a silent no-op on images. The mirror is baked into the sampled dot grid, so it's honoured identically in the laser engrave, the mill relief, and both previews (not just the on-canvas drawing). Mirroring an engrave is common — e.g. cutting the reverse side, or correcting a mirrored source. New `.rcam` `image.flipX` / `flipY` booleans (additive, default false) — [authoring guide](docs/rcam-format-v2.md) / [schema](public/schema/rcam-v2.schema.json).
- **Engrave images can be rotated.** Placing an image for a laser engrave or a mill relief no longer forces it upright — rotate it like any other entity and the toolpath follows. The scan pattern is computed in the image's own frame and each point is lifted through the rotation, so the beam/bit sweeps along the image's *tilted* rows (boustrophedon, overscan, and depth-stepdown all rotate with it); the flat laser preview and the 3-D relief preview tilt to match. Unrotated images post byte-identically to before. The `.rcam` `image.angle` field (already present) is now honoured instead of pinned to 0 — [authoring guide](docs/rcam-format-v2.md) / [schema](public/schema/rcam-v2.schema.json) updated.
- **Engrave images: exact rotation angle in Properties** — the image Properties panel gains an **Angle** field (alongside Width/Height), so you can read and set an exact rotation as well as drag the rotate handle. Replaces the old axis-aligned lockout note now that rotation is honoured.
- **Engrave images: tune brightness/contrast at import** — importing a photo for engraving now opens an **Adjust Image for Engraving** dialog with a live greyscale preview and brightness/contrast sliders (the preview is exactly what the machine reproduces — dark = stronger burn / deeper carve, white = untouched). The adjustment is baked into the stored greyscale buffer, so it feeds laser power and mill relief depth identically with no new format fields. **Reset** returns to the original tones; **Cancel** aborts the import. Re-tuning after placement means re-importing.
- **Engrave preview shows burn intensity** — the flat laser preview now shades each raster-engrave run by its beam power instead of drawing every dot the same red, so a photo engrave reads as a tonal image (darker source areas → stronger mark) and you can judge the result before cutting. Vector cut/engrave paths are unchanged (full-strength beam glow + core).
- **Job metadata on a project** — Project Settings gains a **Job** section with optional **Job**, **Revision**, and **Notes** fields. They're purely informational (no effect on geometry or toolpaths) but travel with the design: non-empty fields are written as comments at the top of the posted G-code (`; Job: …`, `; Revision: …`, `; Notes: …`) so a cut file is traceable back to its part and rev. Stored in the `.rcam` as an optional top-level `metadata` object (additive; all-blank is omitted) — documented in the [authoring guide](docs/rcam-format-v2.md) and [schema](public/schema/rcam-v2.schema.json).
- **CAM: Tabs by spacing** — profile holding tabs can now be placed **by spacing** (one roughly every *N* mm of perimeter) instead of a fixed **count**, so a bigger part automatically gets proportionally more tabs. Pick the mode in the Tabs section; the `.rcam` `tabs` object gains optional `strategy` (`"count"`|`"spacing"`) and `spacing` fields (additive — old count-based files are unchanged).
- **CAM: Greyscale relief carving (CNC mill)** — the image engrave that lasers do by modulating beam power, a mill now does by modulating **Z depth**: import an image, add an **Engrave** toolpath in a mill document, and the darkness of each pixel becomes carved depth (darkest = the cut `depth`, white = the surface) — a 2.5-D relief. It needs a **ball-nose** (the smooth-relief tool, and the default) — a V-bit is allowed but carves an engraving-like result (cone per dot) and is flagged with a note; a flat end mill is rejected. The default stepover scales with the cutter (~10% of diameter). New Cut-section controls **Relief stepover** / **dot pitch** / **Invert** / **Tone curve (gamma)** — the gamma reshapes how mid-tones map to depth so a photo doesn't read flat (`depth ∝ darkness^gamma`) — plus a live **cut-time estimate** (a relief is a long job — tens of minutes to hours — so the dialog shows ~time, rows, and passes up front). The 3-D preview renders the carved relief (showing the real tool-envelope/scallop). Depth is reached over `stepdown` passes so a small bit never plunges the whole relief at once. Reuses the `image` entity and the `rasterLineInterval`/`rasterDotPitch`/`rasterInvert`/`reliefGamma` op fields (documented in the [guide](docs/rcam-format-v2.md) / [schema](public/schema/rcam-v2.schema.json)). Roughing-then-finishing and tool-envelope-aware depth are deferred — for now it's a single finish pass, best for shallow reliefs.
- **CAM: Greyscale raster laser engraving** — **File → Import Image…** brings a photo (PNG/JPEG/…) onto the canvas as a placeable, resizable image (downscaled to ≤1000 px and stored greyscale; embedded in the `.rcam` like fonts). Add a laser **Engrave** toolpath targeting it and the head sweeps the image in horizontal scan rows, modulating beam power per dot — darker pixel = more power. The image is box-averaged to a physical dot grid, so output is bounded by the **Line interval** / **Dot pitch** you set (not the photo's megapixels) and detail finer than the beam is averaged in, not aliased. Controls: line interval, dot pitch (blank = square dots), darkest power (`Power %`) down to **Min power**, **Invert** (engrave light areas), and **Overscan** (run-up/run-down so row edges don't over-burn). Images are kept axis-aligned for now (the engrave doesn't yet honour rotation). New op fields `rasterLineInterval`/`rasterDotPitch`/`rasterMinPower`/`rasterInvert` and the `image` entity + top-level `images` array are documented in the [authoring guide](docs/rcam-format-v2.md) and [schema](public/schema/rcam-v2.schema.json).
- **CAM: V-carve flat-tip bits** — a V-bit's `tipDiameter` (the small flat at the point) is now folded into the carve depth: the tip flat rides the stock surface, so material within the flat radius of a wall stays at the surface and `depth(r) = max(0, r − tipDiameter/2) / tan(½·vAngle)`. Sharp bits (`tipDiameter` 0) are unchanged. Applies to both the posted G-code and the 3D preview, and a tool-library V-bit's flat now flows through to the operation.
- **Help → Privacy & Analytics dialog** — view and change both consents (usage analytics and session replay) at any time, not just on first visit. Turning a consent off applies immediately (opts out of capture and stops any active recording); Do Not Track is reflected and locks the controls.
- **CAM: Laser output** — set the machine type to **laser** (Settings → Machine type) to post fixed-Z beam G-code instead of spindle/Z toolpaths. Supports vector **cut** (profile, with optional `kerfWidth` compensation), vector **engrave** (centreline), and **area-fill engrave** (`laserFill` floods closed shapes with scan lines at `laserFillSpacing`, with letter counters left clear). Beam control uses `laserPower` (0–100 %) scaled to an `S` word and `laserPasses` repeats in place of stepdown; `G0` travels keep the beam off. Reuses the existing XY geometry (kerf offset, arc-fitting, text outlines, region grouping). The `.rcam` format gains a top-level `machineKind` (`"mill"` | `"laser"`, default `"mill"`) and the operation fields `laserPower`/`laserPasses`/`kerfWidth`/`laserFill`/`laserFillSpacing` (documented in the [authoring guide](docs/rcam-format-v2.md) and [schema](public/schema/rcam-v2.schema.json)).
- **CAM: Selectable laser post-processors** — each laser controller is a separate, editable file under `src/cam/laserposts/`: GRBL/FluidNC (`M4` dynamic, default), GRBL/FluidNC (`M3` constant), Marlin (`M3`, 0–255), Smoothieware (inline `S` 0–1 per cut move), and LinuxCNC (PWM spindle). The generator drives them through one `LaserPost` interface (program start, beam on/off, power encoding, modal-vs-inline power). The New Project and Machine Settings dialogs swap the post-processor dropdown between mill posts and laser controllers by machine type. Stored in `postProcessor`; legacy laser files (`"grbl"`) map to the GRBL dynamic head.
- **CAM: Flat laser preview** — laser documents draw the actual beam cut paths as a glowing overlay on the 2D canvas (the laser analogue of the mill's 3D stock preview); the View-menu toggle relabels to **Laser Preview**. The preview and the G-code share one geometry pass, so it shows exactly what will cut.
- **New Project: machine type** — the New Project dialog gains a **Machine type** (CNC Mill/Router | Laser) selector that sets `machineKind` up front; choosing Laser swaps the controller list to the laser posts and grays out the mill-only options (tool changer, coolant, Z-origin).
- **CAM: Laser air assist** — a per-op `airAssist` toggle emits the post-processor's air command (`M8`/`M9` by default, overridable per controller), turned on before the first op that requests it, held across consecutive ops that do, and off otherwise and at program end.
- **CAM: Laser fill overscan** — `laserOverscan` runs the head past each fill scan line's ends with the beam off (explicit `S0`/`S<power>` run-up/run-down), so it's already at full speed when the beam fires — preventing darker over-burned edges, especially at constant power. 0 = off.
- **Laser UI gating** — in a laser document the toolpath dialog offers only Cut/Engrave (hiding tool, cut, tabs, and lead sections), and the "Manage Tools" button is hidden (tools are a milling concept).
- **CAM: Laser material test** — a "Material Test" generator (shown in the toolpath panel in laser mode) drops in a grid of squares that sweep **power** (rows) against **speed** (columns), with engraved axis labels, so you can dial in settings for a new material. Two modes: **Engrave** fills each square (find the cleanest mark), **Cut** traces each square's outline at a chosen pass count (find the minimum that cuts through — cells that do drop out). Each cell is its own op carrying its power/feed; the geometry is grouped for easy moving/deletion.

## [1.0.0] — 2026-06-21

### Added
- **`.rcam` v2 format** — a published [JSON Schema](public/schema/rcam-v2.schema.json) and [authoring guide](docs/rcam-format-v2.md) document the file format (entity point-key vocabularies, constraint/dimension semantics, CAM operations). A drift-guard test validates every bundled example against the schema. Lets external tools and AIs author `.rcam` files reliably. v2 drops transient editor/selection state from the file (a `.rcam` describes a design, not a session) and **embeds the fonts** used by text entities so a saved job reproduces its glyph outlines — and toolpaths — on any machine. Version-1 files open and are upgraded automatically.
- **DOF-based entity colouring** — entities are coloured blue (under-defined) or their normal colour (fully defined) after each solve. Over-constrained / conflicting sketches are highlighted red. Analysis uses RREF null-space decomposition so that mutual dependencies between entities are handled correctly.
- **Driven (reference) dimension UI** — non-driving dimensions now display their value in parentheses `(50.00 mm)` in a muted colour, matching the SolidWorks / FreeCAD convention.
- **Chamfer tool** — trims two meeting line ends by a user-typed distance and inserts a straight bevel line with coincident constraints at both ends. Mirrors the fillet tool workflow.
- **Over-constrained feedback** — extends the existing status-bar warning with per-entity red colouring when the solver fails to converge.
- **Slot tool** (`U`) — two-click slot geometry with arc caps and parallel sides, fully constrained by coincident and equal-radius constraints.
- **Polygon tool** (`N`) — regular polygon with configurable side count (`[` / `]`); produces a closed polyline.
- **Linear Pattern** — parametric array of geometry in an X/Y grid; spacing fields accept variable expressions.
- **Circular Pattern** — parametric array around a centre point with configurable count and total angle.
- **Text entity system** — full OpenType font support; double-click any text entity to edit in place.
- **CAM: Pocket clearing** — adaptive contour-parallel clearing (default; concentric offset loops that wrap islands with no per-row lifting and ramped entry) or classic zig-zag raster, selectable per operation; both respect islands and flood-fill region picking.
- **CAM: Line-type constraints on polyline segments** — apply horizontal/vertical/parallel/perpendicular/collinear/equal/angle/tangent/point-on-line to an individual polyline segment (click it in the select tool) without exploding the polyline.
- **CAM: Engrave arcs** — standalone arcs now produce real `G2`/`G3` toolpaths; profile/pocket of an open arc/line/bezier emits an explanatory `; NOTE:` instead of silently dropping it.
- **CAM: Lead-in / lead-out arcs** — tangential entry/exit for profile cuts.
- **CAM: Tabs / bridges** — automatic tab insertion to hold parts during cutting.
- **CAM: Tool Library Manager** — named tool definitions with diameter, flute count, feed/speed presets.
- **CAM: WebGL toolpath preview** — 3D preview of generated cut paths.
- **CAM: Finishing pass** — optional per-operation finishing pass (profile + pocket) leaves a thin radial allowance (`finishAllowance`, default 0.2 mm) on the walls during stepdown roughing and removes it in a final full-depth wall lap, cleaning the ridges left between depth levels.
- **CAM: Drill pecking** — optional `peckDepth` drills holes in increments with full retract between pecks (G83-style) to clear chips.
- **CAM: Coolant** — per-operation coolant (off / mist `M7` / flood `M8`, `M9` off), gated behind a machine-wide "has coolant" capability so non-coolant machines are never prompted.
- **CAM: End-of-program park** — optional `endPosition` rapids the tool to a work-coordinate position (e.g. 0,0) at safe Z before `M30`.
- **CAM: Export selected toolpaths** — tick a subset of toolpaths and export them to a single G-code file (e.g. all the operations that share a tool).
- **CAM: Chamfer (V-bevel) operation** — bevels an edge with a V-bit by specifying the bevel **width**; the plunge depth is derived from the bit angle (`depth = width / tan(½·vAngle)`), with a live depth/angle readout. `chamferSide` (`on`/`outside`/`inside`) places the bevel relative to the edge. Optional **Sharpen corners** pulls the tip up into each sharp inside corner (tapering the bevel to the surface at the vertex) so corners come to a crisp point instead of a rounded fillet. Targets closed contours (pocket boundaries, profiles) and open edges; mirrored in the 3D preview. Designed for Shaker-style pocket chamfers.
- **CAM: V-carving** — variable-depth carving with a V-bit. The cut depth tracks each point's distance from the region wall (offset-peeling), so strokes taper to a sharp medial-axis spine and bottom out flat once they reach the set max depth. Carves text (letter counters are recognised as holes), directly-selected closed shapes, and **flood-fill-picked regions with islands**; the radial pass pitch (`vStep`) sets floor smoothness. Mirrored in the 3D preview.
- **Toolpath dialog placement** — the Add/Edit Toolpath dialog opens on the right side of the screen and remembers its last dragged position across sessions.
- **Privacy-respecting analytics** — usage analytics are sent only after explicit consent (banner), Do-Not-Track is honoured, and nothing is captured otherwise.
- **SVG export improvements** — exports clean paths with layer colour preservation.

### Changed
- Test suite unified under Vitest (`npm test`) and run in CI; three known solver drag-drift cases are documented as expected failures.
- CamBar's monolithic `openDialog` split into focused section builders; pure CAM helpers extracted to `camBarHelpers.ts`.
- **CAM: Profile lead entry point** — when a lead-in/out is configured, profiles now anchor the lead (and plunge) at the **midpoint of the longest edge** instead of a corner, for a gentler entry and a witness mark on a flat run. Plain profiles with no lead are unchanged (still start at the natural corner).
- **CAM: Circular pockets** now clear with smooth concentric `G2` arcs and a true **helical (`G2`+Z) entry**, replacing the old straight-plunge raster — smoother walls and a gentler descent.
- **CAM: 3D preview fidelity** — the stock simulation now mirrors lead-in/out moves (and the mid-side start), so the preview matches the generated G-code; tabs were already shown. Machine configuration (post-processor, tool changer, coolant capability, custom start/end G-code) is consolidated into a single top-bar **Settings** dialog instead of being split across panels.
- **CAM: Profile arc-fitting** — tool-compensated profiles now post curved runs as smooth `G2`/`G3` arcs instead of many short `G1` facets (fitted within a 0.05 mm tolerance; swept-angle capped so a circle splits into a few well-conditioned arcs). Straight-edged profiles are byte-identical to before.

### Fixed
- Constraint solver: under-constrained geometry no longer rotates unexpectedly when a driving dimension value is changed. Non-pinned DOFs are always anchored (Tikhonov regularisation, weight 1e-3) so the solver picks the minimum-displacement solution in all situations, not just during drag.
- **Pocket region picking** now recognises closed outlines made of mixed curves (lines + arcs/beziers), e.g. a rectangle with a filleted corner — previously such shapes couldn't be hovered or picked.
- **Pocket offset direction** is now winding-independent — a clockwise outline no longer inverts inside/outside.
- **Pocket pass ordering** — each depth level is fully cleared (rough then finish walls) before descending, instead of roughing all depths then re-cutting shallow walls.
- Tangent-to-arc constraints whose contact point falls outside the arc's sweep now raise a non-blocking warning.
- Contiguous-chain selection no longer mistakes a line's midpoint for an endpoint, so chained line segments link correctly.
